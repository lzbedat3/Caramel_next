# The Pour Menu and Admin Restyle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle the admin portal to a dark caramel look, then replace the public menu with "The Pour" from the approved prototype, with "my table", a summary view, a link-rich ending and a full PWA.

**Architecture:** Both admin and public UI already read colours from CSS variables in `styles/globals.css`, so the admin restyle is a token swap plus primitive and sweep fixes. The Pour is a server-rendered semantic list enhanced by a framework-free canvas engine ported from the prototype; React components pass DOM elements to the engine and the engine positions and lights them. Data services, server actions, auth and the database are untouched.

**Tech Stack:** Next.js 16.3.3 (App Router), React 19, TypeScript strict, Tailwind CSS v4, Supabase JS, Vitest (new, dev only).

**Spec:** `docs/superpowers/specs/2026-10-02-pour-menu-design.md`
**Prototype (source of truth for look, motion and engine code):** `docs/superpowers/specs/2026-10-02-pour-prototype.html`

## Global Constraints

- Work on branch `pour-menu`. Never commit to `main`.
- Two files had uncommitted owner changes before this work: `app/admin/(protected)/layout.tsx` and `lib/supabase/proxy.ts`. Do not revert, reformat or stage them.
- Do not change `supabase/`, `services/`, `features/*/actions.ts`, `lib/supabase/`, `lib/auth/`, `proxy.ts`, `types/database.ts`.

- Public components contain no restaurant text. Strings come from `lib/i18n`; brand values from `config/site.ts` and `config/pour-theme.ts`; content from `PublicHomeContent`.
- Fonts: Ubuntu for Latin and numbers, Heebo for Hebrew, Cairo for Arabic, via the existing `lib/fonts.ts` variables.
- Icons: inline SVG components only. No icon fonts, emoji or raster icons.
- Summary button label is `סיכום`. No city name and no scroll hint in the opening.
- Rights line: "© {year} כל הזכויות שמורות ל-Darb Rest", name linked to `https://darb.co.il`.

- Never write the owner's admin credentials to any file.
- New dependency allowed: `vitest` (dev). No others.
- Every task ends with `npm run lint && npm run typecheck` passing.

## Review Focus

1. **A restaurant with zero categories or zero dishes.** The page must render the opening and ending without the engine throwing. Covered in Task 8 (engine guards) and Task 9 (browser check with an empty model).
2. **A dish with no image, or whose image fails.** Must show the lettered ring, not a broken image. Covered in Task 9.
3. **A stored table that references dishes since deleted, hidden or made unavailable.** Must be dropped silently and totals recomputed from current prices. Covered by the reducer tests in Task 6.
4. **`localStorage` unavailable or holding malformed JSON** (private mode, old data). The table must start empty and keep working in memory. Covered by storage tests in Task 6.
5. **Very long dish names and a narrow phone (320 px).** Text must wrap inside its bay without overlapping the ring. Covered by the 320 px browser check in Task 12.
